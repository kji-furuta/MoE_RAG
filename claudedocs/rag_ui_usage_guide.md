## 1. システムアクセス方法

### 1.1 Webブラウザでのアクセス

1. **ブラウザを起動**（推奨: Chrome, Firefox, Edge）

2. **アドレスバーに入力**:
   ```
   http://localhost:8050
   ```

3. **メインダッシュボードが表示**されます：
   ```
   ┌─────────────────────────────────────────┐
   │  AI Fine-tuning Toolkit (AI_FT_7)      │
   │                                         │
   │  [ Fine-tuning ]  [ RAG検索 ]          │
   │  [ モデル管理 ]   [ システム情報 ]      │
   └─────────────────────────────────────────┘
   ```

4. **「RAG検索」ボタンをクリック**

### 1.2 直接RAGページにアクセス

```
http://localhost:8050/rag
```

### 1.3 システムが起動していない場合

```bash
# Dockerコンテナ起動
cd docker
docker-compose up -d

# Webサーバー起動
docker exec ai-ft-container bash /workspace/scripts/start_web_interface.sh

# または直接起動
docker exec ai-ft-container python -m uvicorn app.main_unified:app --host 0.0.0.0 --port 8050 --reload
```

## 3. 高度な検索オプション

### 3.1 検索件数の調整

**設定箇所**: 「高度な設定」→「検索件数」

| 設定値 | 用途 | 応答速度 | 精度 |
|--------|------|---------|------|
| **3件** | 簡単な質問 | ⚡ 高速 | 🔵 標準 |
| **5件** | 一般的な質問（推奨） | 🔵 標準 | 🟢 高 |
| **10件** | 複雑な質問 | 🔶 やや遅い | 🟢 最高 |

**使用例**:
```
簡単な質問: 「設計速度の定義は？」
→ 検索件数: 3件

複雑な質問: 「山岳地での道路設計における曲線半径の決定方法と、
           地形条件による制約事項について詳しく教えてください」
→ 検索件数: 10件
```

### 3.2 引用スタイルの選択

**設定箇所**: 「高度な設定」→「引用スタイル」

#### オプション1: 簡潔スタイル
```
回答: 最小曲線半径は280mです。[1][2]

引用:
[1] 道路構造令の解説と運用
[2] 交通施設の技術基準
```

#### オプション2: 詳細スタイル（推奨）
```
回答: 最小曲線半径は280mです。

引用:
[1] 道路構造令の解説と運用（令和3年）
「設計速度80km/hの場合、最小曲線半径は280メートルとする。」
出典: p.45, セクション3.2

[2] 交通施設の技術基準とその解説（愛知）
「曲線半径は設計速度に応じて決定する。80km/hでは280m以上を確保すること。」
出典: p.32, セクション2.4
```

#### オプション3: アカデミックスタイル
```
回答: 最小曲線半径は280mです。

参考文献:
[1] 日本道路協会. (2021). 道路構造令の解説と運用（令和3年版）. p.45.
[2] 愛知県. (2022). 交通施設の技術基準とその解説. p.32.
```

### 3.3 専門機能の有効化

#### 数値処理機能
**用途**: 計算が必要な質問に対応

**使用例**:
```
質問: 「設計速度60km/hと80km/hの最小曲線半径の差は？」

☑ 数値処理を有効化
→ 回答: 170m - 280m = 110m の差があります。
```

#### 設計基準検証機能
**用途**: 設計値の妥当性チェック

**使用例**:
```
質問: 「曲線半径250mは設計速度80km/hで適切ですか？」

☑ 設計基準検証を有効化
→ 回答: ❌ 不適切です。
        最小曲線半径280mを下回っています（-30m）。
        道路構造令に違反しています。
```

## 7. トラブルシューティング

### 7.1 よくある問題と解決方法

#### 問題1: 「検索結果が見つかりません」

**原因**:
- ドキュメントがインデックス化されていない
- 質問が曖昧すぎる

**解決策**:
```bash
# ドキュメントを再インデックス
docker exec ai-ft-container python /workspace/scripts/rag/index_documents.py

# または、より具体的な質問に変更
❌ 悪い例: 「道路について」
✅ 良い例: 「設計速度80km/hの道路における最小曲線半径」
```

#### 問題2: 「サーバーに接続できません」

**解決策**:
```bash
# サーバーが起動しているか確認
curl http://localhost:8050/rag/health

# 起動していない場合
docker exec ai-ft-container python -m uvicorn app.main_unified:app --host 0.0.0.0 --port 8050 --reload
```

#### 問題3: 「応答が遅い」

**原因と解決策**:

| 原因 | 解決策 |
|------|--------|
| 検索件数が多すぎる | 検索件数を5件以下に設定 |
| ドキュメント数が多い | インデックスの最適化実行 |
| GPUメモリ不足 | `nvidia-smi`で確認、不要なプロセス停止 |

**インデックス最適化**:
```bash
docker exec ai-ft-container python -c "
from src.rag.indexing.vector_store import QdrantVectorStore
store = QdrantVectorStore()
store.optimize()
print('✅ 最適化完了')
"
```

#### 問題4: 「引用が表示されない」

**確認事項**:
1. ブラウザのJavaScriptが有効か確認
2. ブラウザのコンソールでエラー確認（F12キー → Consoleタブ）
3. 引用スタイルが「詳細」になっているか確認

**ブラウザキャッシュクリア**:
```
Chrome: Ctrl+Shift+Delete → キャッシュをクリア
Firefox: Ctrl+Shift+Delete → キャッシュをクリア
Edge: Ctrl+Shift+Delete → キャッシュをクリア
```

#### 問題5: 「PDFアップロードが失敗する」

**確認事項**:
1. ファイルサイズ: 100MB以下
2. ファイル形式: PDF, DOCX, TXT, MD
3. ファイル名: 日本語可、特殊文字は避ける

**エラーメッセージ別の対応**:
```
「ファイルが大きすぎます」
→ PDFを分割してアップロード

「処理タイムアウト」
→ タイムアウト設定を延長:
  docker exec ai-ft-container \
    sed -i 's/timeout=60/timeout=300/' app/main_unified.py
  docker restart ai-ft-container

「OCR処理エラー」
→ Tesseract OCRが正しくインストールされているか確認:
  docker exec ai-ft-container tesseract --version
```

### 7.2 システムログの確認

```bash
# リアルタイムログ監視
docker logs -f ai-ft-container

# エラーログのみ表示
docker logs ai-ft-container 2>&1 | grep -i error

# 最新100行のログ表示
docker logs ai-ft-container --tail 100
```

### 7.3 システム再起動

```bash
# Dockerコンテナ再起動
docker restart ai-ft-container

# 完全再起動（クリーンスタート）
docker-compose down
docker-compose up -d --build
```
