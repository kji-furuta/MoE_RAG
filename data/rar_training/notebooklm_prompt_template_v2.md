# NotebookLM RAR形式データ生成プロンプト (Version 2.0)

## 📋 概要
このプロンプトは、NotebookLMを使用してRAR (Retrieval-Augmented Reasoning) 形式の高品質な学習データを生成するための最適化されたテンプレートです。

**改善点 (Phase 1からの学習)**:
- ✅ 正しいJSON配列形式での出力を明示
- ✅ LaTeX記号の適切なエスケープ指示
- ✅ 引用元ファイル名の検証強化
- ✅ Chain-of-Thought品質基準の明確化

---

## 🎯 プロンプト本体

```
あなたは土木工学・道路設計の専門家です。以下の文書を使用して、RAG (Retrieval-Augmented Generation) システムの学習データを生成してください。

### 📌 出力形式の重要事項

**必須**: 出力は必ず単一のJSON配列形式 `[{...}, {...}, ...]` で、各オブジェクトは1行に圧縮してください。
- ❌ 複数行の整形されたJSONは禁止
- ❌ オブジェクト間のカンマ区切りは禁止
- ✅ 正しいJSON配列形式: `[{"id":"DES-001",...},{"id":"DES-002",...}]`

### 📄 利用可能な文書リスト

以下のファイル名のみを`source`フィールドに使用してください:

1. 【日本道路協会】道路構造令の解説と運用（令和3年）_R3年3月-5.pdf
2. 03_交通施設の技術基準とその解説（愛知_設計手引き）.pdf
3. 【日本道路協会】舗装設計施工指針（令和4年度版）_R4年11月.pdf
4. （参考）04_道路（愛知_設計手引き）.pdf
5. 【日本道路協会】道路橋示方書・同解説（Ⅴ耐震設計編）_R9年11月.pdf

**注意**: 上記リスト以外のファイル名を使用しないでください。架空のファイル名は生成しないでください。

### 🎯 生成するデータ形式

各エントリーは以下の構造で生成してください:

```json
{
  "id": "DES-001",
  "instruction": "具体的な技術的質問（設計速度、曲線半径、舗装厚さなど）",
  "documents": [
    {
      "source": "【日本道路協会】道路構造令の解説と運用（令和3年）_R3年3月-5.pdf",
      "is_oracle": true,
      "content": "正解を含む文書の本文（100-300文字程度）"
    },
    {
      "source": "03_交通施設の技術基準とその解説（愛知_設計手引き）.pdf",
      "is_oracle": false,
      "content": "関連するが直接的な答えではない文書（distractor）"
    }
  ],
  "output": {
    "chain_of_thought": "段階的な推論プロセス（3-5ステップ）。必ず「1.」「2.」などの番号付けと、「から」「ため」「により」「したがって」などの推論語を使用してください。",
    "final_answer": "明確で簡潔な最終回答",
    "citations": [
      {
        "source": "【日本道路協会】道路構造令の解説と運用（令和3年）_R3年3月-5.pdf",
        "quote": "回答の根拠となる引用文（40-100文字）"
      }
    ]
  }
}
```

### ✅ Chain-of-Thought品質基準

**必須要件**:
1. **ステップ化**: 必ず「1.」「2.」「3.」などで推論を段階化
2. **推論語の使用**: 「から」「ため」「により」「したがって」「これにより」などを含める
3. **長さ**: 最低50文字以上（理想は100-200文字）
4. **論理性**: 各ステップが前のステップから論理的に導かれる

**良い例**:
```
1. 設計速度80km/hの道路について検討する。道路構造令によれば、設計速度に応じた最小曲線半径が定められている。
2. 80km/hの設計速度の場合、平面曲線の最小半径は280mと規定されている。
3. したがって、この道路では半径280m以上の曲線を採用する必要がある。
```

**悪い例** (短すぎる、ステップ化なし):
```
道路構造令で定められている値を確認すると280mです。
```

### 📊 Oracle vs Distractor比率

- **Oracle文書**: 60-70%（正解を含む文書、`is_oracle: true`）
- **Distractor文書**: 30-40%（関連するが正解でない文書、`is_oracle: false`）

**重要**: 各エントリーに最低1つのOracle文書と、可能であれば1-2つのDistractor文書を含めてください。

### 🔧 技術的注意事項

#### LaTeX記号のエスケープ
JSONでは`\`記号を`\\`としてエスケープする必要があります:
- ❌ `\sigma` → JSON解析エラー
- ✅ `\\sigma` → 正しい
- ❌ `\alpha` → JSON解析エラー
- ✅ `\\alpha` → 正しい

#### 引用文の品質
- 引用は40-100文字程度
- 回答の根拠となる具体的な数値や基準を含む
- 文章として完結している（途中で切れていない）

### 📝 生成する質問の種類（バランスよく）

1. **設計基準値**: 「設計速度○○km/hの最小曲線半径は？」
2. **舗装設計**: 「交通量○○台/日の場合の舗装厚さは？」
3. **構造物設計**: 「橋梁の耐震設計における○○の基準値は？」
4. **交通安全**: 「視距の確保における○○の規定は？」
5. **材料・施工**: 「舗装材料の○○に関する基準は？」

### 🎯 生成数とID命名規則

- **生成数**: 50件
- **IDフォーマット**: `DES-XXX` (XXXは001から連番)
- **連続性**: 前回の最終IDの次から開始

### ✨ 出力例（完全版）

```json
[{"id":"DES-001","instruction":"設計速度80km/hの道路における平面曲線の最小半径はいくつですか？","documents":[{"source":"【日本道路協会】道路構造令の解説と運用（令和3年）_R3年3月-5.pdf","is_oracle":true,"content":"道路の存する地域の地形の状況等により特別な理由がやむを得ない場合において、第30条第3項の規定により地方部... その他の 道路 第 3 種に該当する道路の平面曲線の最小半径は、設計速度が毎時80キロメートルの場合、280メートルとする。"},{"source":"03_交通施設の技術基準とその解説（愛知_設計手引き）.pdf","is_oracle":false,"content":"交通施設の設計においては、適切な視距の確保が重要である。見通しの悪い箇所では、運転者が前方の障害物や他の車両を早期に発見できるよう配慮が必要となる。"}],"output":{"chain_of_thought":"1. 設計速度80km/hの道路について、道路構造令に基づいて平面曲線の最小半径を確認する必要がある。2. 道路構造令の解説によれば、地方部その他の道路第3種に該当する道路では、設計速度に応じた最小曲線半径が規定されている。3. 設計速度80km/hの場合、最小半径は280メートルと明記されている。したがって、この基準値を適用する。","final_answer":"設計速度80km/hの道路における平面曲線の最小半径は280メートルです。","citations":[{"source":"【日本道路協会】道路構造令の解説と運用（令和3年）_R3年3月-5.pdf","quote":"設計速度が毎時80キロメートルの場合、280メートルとする"}]}},{"id":"DES-002","instruction":"次の質問...","documents":[...],"output":{...}}]

### 🚀 実行指示

上記の形式に従って、50件のRAR形式データを生成してください。

**重要な確認事項**:
- ✅ 出力は単一のJSON配列形式
- ✅ 各オブジェクトは1行に圧縮
- ✅ ファイル名は提供されたリストのみ使用
- ✅ Chain-of-Thoughtは必ずステップ化（番号付き）
- ✅ LaTeX記号は適切にエスケープ（`\\sigma`など）
- ✅ 引用は40-100文字で完結した文章
```

## 📊 品質チェックリスト

生成後、以下を確認してください:

### JSON形式
- [ ] 単一のJSON配列形式 `[{...}, {...}]`
- [ ] 各オブジェクトが1行に圧縮
- [ ] オブジェクト間にカンマなし（配列内の正しいカンマのみ）
- [ ] JSON.parseで解析可能

### データ品質
- [ ] 全エントリーに`id`, `instruction`, `documents`, `output`が存在
- [ ] Chain-of-Thoughtが番号付きでステップ化
- [ ] Chain-of-Thoughtに推論語が含まれる（「から」「ため」など）
- [ ] 引用文が40-100文字で完結
- [ ] ファイル名が提供リストから選択

### バランス
- [ ] Oracle文書が60-70%
- [ ] 質問の種類が多様（設計基準、舗装、構造物など）

## 🔄 バッチ生成ワークフロー

### 第1バッチ（50件）: DES-001 ~ DES-050
- プロンプトをそのまま使用
- 生成後、品質チェック実施

### 第2バッチ（50件）: DES-051 ~ DES-100
- プロンプトのIDフォーマット部分を更新: `DES-051から連番`
- 「前回生成した質問と重複しないように」を追加

### 第3バッチ以降
- 同様のパターンで継続
- 累積チェック: 重複質問の検出と除外

## 📝 使用方法

1. NotebookLMで対象PDF文書をアップロード
2. 上記プロンプトをコピー＆ペースト
3. 生成されたJSON配列を保存
4. 自動検証スクリプトで品質チェック
5. 必要に応じて修正・補完
